# API Conventions

## Base

- Prefix `/api/v1`. Breaking changes bump the prefix; nothing else.
- Resource paths plural, kebab-case. Payload fields `snake_case`.
- **Nobody but a developer reads this surface, so it is English** (ADR-0013):
  field names, error codes, route path segments and query parameters.
- **Except glossary vocabulary, which is never translated** (invariant 1).
  `/notas-empenho`, `/atas`, `/insumos`, `/notas-fiscais`, `/usuarios`,
  `/fornecedores`, and fields such as `saldo`, `perfil`, `valor_estimado`,
  `data_emissao`, `processo_sei`.
- **The tie-break for compounds:** a name built around a glossary noun keeps the
  whole Portuguese expression; a name with no glossary noun becomes English.
  Never translate a compound word by word. So `SALDO_INSUFICIENTE` and
  `/notas-empenho/{id}/avancar` stay whole, while `CREDENCIAIS_INVALIDAS`
  becomes `INVALID_CREDENTIALS` and `/convites/{token}/ativar` becomes
  `/invites/{token}/activate`. `SALDO_INSUFFICIENT` and `/usuarios/{id}/block`
  read as neither language and are what this rule exists to prevent.
- Database columns are Portuguese regardless (ADR-0013), so a payload field and
  the column behind it need not share a name. `password` over `senha_hash` is
  correct, not a mismatch to fix.

## Verbs

| Verb | Use |
| --- | --- |
| GET | Reads. Always safe, always idempotent. |
| POST | Creation, and **state transitions as sub-resource actions** |
| PATCH | Partial edit of mutable attributes only |
| PUT | Not used |
| DELETE | Not used on auditable entities. Cancel or deactivate instead. |

State transitions are `POST /notas-empenho/{id}/avancar`, not
`PATCH {"status": ...}`. The guard, the required justification and the
permission are then part of the contract rather than something the client has to
know. It also makes the audit `acao` unambiguous.

## Responses

Success returns the resource. Errors always use this shape:

```json
{
  "error": {
    "code": "SALDO_INSUFICIENTE",
    "message": "Saldo insuficiente na ATA 014/2025. Disponível: R$ 50.000,00. Necessário: R$ 78.000,00.",
    "fields": { "valor_estimado": "Valor excede o saldo disponível." },
    "correlation_id": "018f3c2e-..."
  }
}
```

- `code` is stable and machine-readable; never localise it.
- `message` is pt-BR, addressed to Carlos, and says what to do next.
- `fields` drives inline field errors in the UI. Per-field messages are the
  stated mitigation for transcription errors (RFC §3.2); a single generic
  "dados inválidos" defeats it. Keys are the payload field names they refer to,
  so they follow the rule above; the values are pt-BR, because the servidor
  reads them.

## Status codes

| Code | Meaning here |
| --- | --- |
| 400 | Malformed request |
| 401 | Absent, expired or invalid token |
| 403 | Authenticated but the profile is not permitted (always audited) |
| 404 | Not found, or not visible to this profile |
| 409 | Domain conflict: invalid transition, insufficient saldo, ineligible ATA |
| 422 | Validation failure on a well-formed request |
| 429 | Rate limited |

422 means "the shape is wrong"; 409 means "the shape is right but the domain
says no". Keeping them distinct lets the frontend decide between a field error
and a blocking dialog without parsing prose.

## Pagination, filtering, sorting

`?page=1&size=25` (max 100), response envelope `{ "items": [...], "total": n,
"page": 1, "size": 25 }`. Filters are explicit query parameters, never a
generic `filter` DSL. Sorting via `?sort=-data_emissao`: the parameter is
English, the key names a payload field, and that one is glossary vocabulary.

## Auth

`Authorization: Bearer <access_token>`. Refresh token in an httpOnly, Secure,
SameSite=Lax cookie; never in localStorage, which is XSS-readable.

## Money and dates

Money as a decimal **string** in JSON (`"78000.00"`), never a JSON number —
IEEE-754 parsing in JavaScript will silently corrupt it. Formatting to
`R$ 78.000,00` is the frontend's job. Dates ISO-8601 with offset.

## Documentation

OpenAPI is generated by FastAPI. Every endpoint's docstring names the spec and
AC it implements, so the generated docs are themselves a traceability artifact.
